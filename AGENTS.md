# AGENTS.md

## Architecture

TanStack Start app (file-based routing under `src/routes`) for Boyd Glass Service, deployed to Netlify. Server-side logic lives in `src/server/*.functions.ts` as TanStack `createServerFn` calls — these are the only place that touch the database, blobs, Stripe, or email.

- `db/schema.ts` — Drizzle schema (Postgres via Netlify Database): `pricingConfig`, `estimates`, `appointments`, `reviews`, `galleryImages`.
- `db/index.ts` — Drizzle client (`drizzle-orm/netlify-db`, no connection string needed).
- `netlify/database/migrations/` — generated by `drizzle-kit generate`. Never hand-edit or apply migrations directly; Netlify applies them at deploy time.
- `src/lib/pricing.ts` — the single source of truth for glass types, labor rates, additional service fees, tax rate, and the `calculateEstimate()` function used by the `/estimate` calculator.
- `src/server/*.functions.ts` — server functions, one file per domain: `estimates`, `appointments`, `reviews`, `gallery`, `admin` (pricing config + CSV export), `payments` (Stripe), `uploads`, plus `email.server.ts` (Resend helper, not a server function).
- `src/middleware/identity.ts` — `requireAuthMiddleware` gates any server function that should only run for a logged-in Netlify Identity user (all admin reads/writes).
- Photos (gallery + appointment uploads) are stored in Netlify Blobs (`gallery-photos`, `appointment-photos` stores) and served through catch-all API routes (`src/routes/api/gallery-image.$.tsx`, `src/routes/api/appointment-photo.$.tsx`) rather than returning signed URLs directly.
- `src/routes/admin/index.tsx` — single-page tabbed dashboard (Appointments, Estimates, Pricing, Gallery, Reviews, Export) gated by `useIdentity()`; shows a login button when signed out.

## Known gap

The admin "Pricing" tab persists edits to the `pricing_config` table, but `src/lib/pricing.ts` (used by the live `/estimate` calculator) is a static module with its own hardcoded rates. Admin edits to `pricing_config` do not yet flow back into the customer-facing calculator — wiring that up would mean loading rates from `pricing_config` (via a public read) into `calculateEstimate` instead of the hardcoded `GLASS_TYPES`/`LABOR_OPTIONS` tables.

## Conventions

- Server functions that mutate or read privileged data use `.middleware([requireAuthMiddleware])`. Public functions (submitting an estimate, booking an appointment, leaving a review) do not.
- Input validation uses Zod via `.inputValidator(schema)` — never `.validator()` (that API doesn't exist in this TanStack Start version).
- File uploads go through `.inputValidator((formData: FormData) => formData)` and are read with `formData.get("file") as File`.
- Money values are stored as Postgres `numeric` (returned as strings by Drizzle) but computed as JS numbers in `pricing.ts`; convert with `String(...)` on write.
- The contact form uses the Netlify Forms static-skeleton pattern (`public/contact-form.html`) because Netlify's build-time form detection can't see React-rendered forms — the React form in `src/routes/contact.tsx` posts to `/contact-form.html`, not `/`.
- Netlify Identity is the only auth system; there is no separate admin password or role table. Anyone who signs up gets dashboard access unless registration is switched to invite-only in the Netlify dashboard (Project configuration > Identity).

## Local development limitations

Netlify Identity, Blobs, and Forms do not fully work under plain `vite dev`; `netlify dev` emulates most of them, but Identity login specifically requires a real Netlify deployment (the `nf_jwt` cookie comes from GoTrue on the live site, not localhost).
